# Make a repository usable by the next agent

Apply the shared [architectural defaults](../phi9t/references/architecture.md)
to execution selection and the newcomer map. Discover the actual program and
data contracts and their Insula or permitted native path; extend the target's
existing owners rather than imposing a template tree or a workflow engine.

Resolve the target and read its instructions, current changes, runtime contract,
normal hooks and existing tools. Choose one useful bounded user journey. Reuse
its actual CLI, API, browser controls or admitted driver. Discover late runtime
prerequisites before starting an expensive broad suite.

Establish readiness through the target's doctor or focused checks. Distinguish
shell-path mistakes, absent dependencies, baseline failures and unavailable
external resources. Prepare missing prerequisites through the owner's supported
flow when authorized. Preserve pins and admission checks.

Exercise one real success and a meaningful refusal in owned fixture state. Check
actual values and absent forbidden effects. Retain inputs, source/runtime identity,
commands, outputs and cleanup evidence. Label narrower host coverage separately
from full device or remote qualification.

Extend or create a small target-owned verification skill. It explains readiness,
launch, drive, evidence and cleanup. Use [packet shape](references/packet.md),
link existing owners and put product-specific commands with their repository.
Run the documented path from its starting state. A fresh reader must be able to
follow it without this conversation. An unexercised recipe stays a draft.

Turn observed recurring failures into [structural corrections](../phi9t-correct/SKILL.md).
Maintain the packet when its behavior changes. Report the actual check coverage,
remaining qualification and integration state. A bootstrap does not imply a
scheduler, deployment, blanket skill installation or automatic merge policy.
