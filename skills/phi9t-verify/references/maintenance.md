# Maintain a behavior map

Bound the pass: every mapped journey for a full audit, or named affected entries
for a change-focused pass. Proposed journeys stay explicitly unproved.

Trace selected entries through current source. Find omitted behaviors in recent
changes, qualify the candidate and drive each declared journey. Distinguish doc
drift, harness failure, missing prerequisite and product regression. Confirm the
intended behavior before editing a recipe. A product failure is not repaired by
weakening its expected result. Product fixes retain their own scope authority.

Use independent fixture state per driver. Share a running app only under its
explicit ownership contract. After surprising behavior, check health and reset
only owned state. Re-drive repaired recipes and preserve failed evidence.

Report the actual journeys and required gates: clean when all declared coverage
agrees; changed when proven packet repairs were needed; blocked when declared
coverage or a required gate cannot finish. Within blocked work, list completed
proof separately. Scheduling maintenance requires a user request.
